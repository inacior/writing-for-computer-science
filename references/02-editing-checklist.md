# Editing and consistency checklist

Use this checklist when revising your own writing and when proofreading the
work of others.

## Approach

- [ ] Adopt the pose of an external critic; pretend to be a reader in the
      intended audience.
- [ ] Edit for brevity and balance; cut material whose content or relevance
      does not justify its length; do not fear shortening.
- [ ] When moving text, check it stays intelligible and appropriate in its new
      context (do not break definitions or argument flow).
- [ ] Set the article aside for a day or two before proofreading it.
- [ ] Get someone else to read it before submitting or distributing it; never
      ignore a proofreader's comments.
- [ ] Proofread on paper after formatting, not only in a text editor.
- [ ] Use a spelling checker — but remember it misses missing/repeated/misused
      words, double stops, and wrong-word misspellings ("or" for "on"/"of").
- [ ] Watch for your own habitual errors: wrong initial letters, anagrams,
      incomplete or run-on sentences.
- [ ] Check tense and singular/plural verb agreement.
- [ ] Check the bibliography carefully: consistent format, enough information
      to locate each reference.
- [ ] Fix layout glitches: broken formulas, isolated lines between tables, bad
      line breaks.
- [ ] Remove **widows** (a paragraph's last line holding a single short word) —
      use a non-breaking space.
- [ ] Remove **orphans** (a heading or the first line after a heading alone at
      the bottom/top of a page) — rewrite until gone.
- [ ] Proofread the whole article at least once for flow and consistency.

## Consistency

- [ ] Are titles and headings consistent with content?
- [ ] Have all terms been defined? Is the style of definition consistent (e.g.,
      all new terms italicized, not just some)?
- [ ] Has terminology been used consistently? Are defined objects always
      described the same way?
- [ ] Are abbreviations/acronyms stated in full at first use, introduced only
      once, and used consistently? (Avoid any used fewer than about four times.)
- [ ] Do all headings use consistent capitalization (maximum or minimum)?
- [ ] Are heading and caption style and wording consistent?
- [ ] Is spelling consistent ("-ise"/"-ize", "disk"/"disc", "dispatch"/
      "despatch")?
- [ ] Is tense used correctly? Are references discussed consistently?
- [ ] Are bold and italic used logically? Is hyphenation consistent?
- [ ] Are units used consistently (ms vs µs)? Is "megabyte" written the same way
      ("Mb" vs "Mbyte")?
- [ ] Are all values of the same type given to the same precision?
- [ ] Are all graphs the same size? Are axis units always given? Do same-unit
      axes share the same label?
- [ ] Are all tables in the same format? Do single/double lines follow a logical
      pattern? Are units given for every value? Are labels consistent?
- [ ] Do all tables share the same orientation (columns vs rows for the same
      properties)?
- [ ] Is the same style used for all algorithms and programs? Consistent
      variable naming, pseudocode syntax, and indentation?
- [ ] In references: is each field formatted consistently? Are italics/quotes
      used appropriately for titles? Is capitalization consistent? Are journal
      and conference names abbreviated the same way? Is the author-name style
      consistent? Do references of the same type have the same core fields?
- [ ] Is display formatting consistent (indentation vs centring; paragraph
      indentation after headings)?
- [ ] Do the parentheses match?

## Style during editing

- [ ] Keep the basic aim: make the paper clear. Lapses are forgiven if the
      reader can follow you.
- [ ] When revising others' text, make minimal changes: correct presentation,
      retain the original flavour, do not impose your own style.
- [ ] Consider the target journal's preferred style for references, figure
      numbering, spelling, table layout, and capitalization.
